Financial News Agentic Workflow System¶

This notebook builds an Investment Research Agent for a stock symbol. It uses Claude through the Anthropic API for planning, classification, extraction, summarization, routing, evaluation and memory. News comes from NewsAPI and Yahoo Finance RSS, with bundled sample files as a backup, and prices come from yfinance. If a call fails or no key is set, each agent uses a rule-based fallback so the notebook still runs.

Workflow patterns

  1. Prompt Chaining: Ingest News -> Preprocess -> Classify -> Extract -> Summarize
  2. Routing: direct each article to an earnings, macro, market, or company-news specialist.
  3. Evaluator-Optimizer: generate analysis, evaluate quality, and refine weak outputs.

Agent functions

  1. Plans its research steps for a stock symbol (section 2).
  2. Uses tools dynamically: news APIs, datasets and yfinance (sections 4 and 5).
  3. Self-reflects on the quality of its output (section 7).
  4. Learns across runs with saved notes and lessons (sections 3, 7 and 8).

Section 10 runs everything end to end for one symbol.

def log_memory_event(stage, payload):
    """Persist a compact memory record for each prompt-chain stage."""
    MEMORY_DIR.mkdir(exist_ok=True)
    record = {
        "run_id": RUN_ID,
        "timestamp_utc": datetime.now(timezone.utc).isoformat(),
        "stage": stage,
        "payload": payload,
    }
    with PROMPT_CHAIN_MEMORY_PATH.open("a", encoding="utf-8") as f:
        f.write(json.dumps(record) + "\n")
    return record


def extract_json_object(text):
    """Extract the first JSON object from an LLM response."""
    if not text:
        return None
    fenced = re.search(
        r"```(?:json)?\s*(\{.*?\})\s*```", text, flags=re.DOTALL
    )
    candidate = (
        fenced.group(1)
        if fenced
        else text[text.find("{") : text.rfind("}") + 1]
    )
    if not candidate:
        return None
    try:
        return json.loads(candidate)
    except json.JSONDecodeError:
        return None


def call_openai_chat(system_prompt, user_prompt):
    api_key = os.getenv("OPENAI_API_KEY")
    if not api_key:
        return None
    payload = {
        "model": OPENAI_MODEL,
        "messages": [
            {"role": "system", "content": system_prompt},
            {"role": "user", "content": user_prompt},
        ],
        "temperature": 0.2,
        "response_format": {"type": "json_object"},
    }
    request = Request(
        "https://api.openai.com/v1/chat/completions",
        data=json.dumps(payload).encode("utf-8"),
        headers={
            "Authorization": f"Bearer {api_key}",
            "Content-Type": "application/json",
        },
    )
    with urlopen(request, timeout=LLM_TIMEOUT_SECONDS) as response:
        data = json.loads(response.read().decode("utf-8"))
    return data["choices"][0]["message"]["content"]


def call_anthropic_messages(system_prompt, user_prompt):
    api_key = os.getenv("ANTHROPIC_API_KEY")
    if not api_key:
        return None
    payload = {
        "model": ANTHROPIC_MODEL,
        "max_tokens": 6000,
        "temperature": 0.2,
        "system": system_prompt,
        "messages": [{"role": "user", "content": user_prompt}],
    }
    request = Request(
        "https://api.anthropic.com/v1/messages",
        data=json.dumps(payload).encode("utf-8"),
        headers={
            "x-api-key": api_key,
            "anthropic-version": "2023-06-01",
            "Content-Type": "application/json",
        },
    )
    with urlopen(request, timeout=LLM_TIMEOUT_SECONDS) as response:
        data = json.loads(response.read().decode("utf-8"))
    return "".join(
        block.get("text", "")
        for block in data.get("content", [])
        if block.get("type") == "text"
    )


def call_llm_json(agent_name, system_prompt, user_payload, fallback_fn):
    """Ask an LLM agent for JSON; use the fallback if the call fails."""
    user_prompt = json.dumps(user_payload, indent=2)
    if LLM_ENABLED:
        try:
            response_text = None
            if LLM_PROVIDER in {"auto", "openai"}:
                response_text = call_openai_chat(system_prompt, user_prompt)
            if response_text is None and LLM_PROVIDER in {
                "auto",
                "anthropic",
                "claude",
            }:
                response_text = call_anthropic_messages(
                    system_prompt, user_prompt
                )
            parsed = extract_json_object(response_text)
            if parsed:
                parsed["decision_source"] = "llm"
                parsed["agent_name"] = agent_name
                return parsed
        except Exception as exc:
            log_memory_event(
                "llm_error", {"agent": agent_name, "error": str(exc)[:300]}
            )
    fallback = fallback_fn()
    fallback["decision_source"] = "deterministic_fallback"
    fallback["agent_name"] = agent_name
    return fallback

2. Agent Function: Planning¶

The planner takes a stock symbol and decides which research steps to run and in what order. It only picks from the tools this notebook actually has. If the LLM gives back a bad plan, it falls back to a fixed default so the run still works.

# tools the planner is allowed to use
PLAN_TOOLS = [
    "read_memory",
    "ingest_news",
    "get_market_context",
    "run_prompt_chain",
    "route_to_specialist",
    "evaluate_and_refine",
    "self_reflect",
    "write_memory",
]


def fallback_research_plan(symbol):
    # fixed order, used when there is no LLM or the LLM plan is unusable
    steps = [
        ("read_memory", f"Check notes from past runs on {symbol}"),
        ("ingest_news", f"Pull recent headlines about {symbol}"),
        ("get_market_context", f"Get price and volume data for {symbol}"),
        ("run_prompt_chain", "Classify, extract signals, and summarize"),
        ("route_to_specialist", "Send each article to the right analyst"),
        ("evaluate_and_refine", "Score the analysis and fix weak spots"),
        ("self_reflect", "Look back at the scores and save lessons"),
        ("write_memory", f"Save what we learned about {symbol}"),
    ]
    return {
        "steps": [{"tool": t, "purpose": p} for t, p in steps],
        "reasoning": "Default order: recall, gather, analyze, check, save.",
    }


def plan_research(symbol, notes=None):
    system_prompt = """
You are a planning agent for a stock research system. Given a stock symbol,
decide which research steps to run and in what order. Only use tools from
available_tools. past_notes are notes from earlier runs on this stock, use
them to decide what needs the most attention. self_reflect looks back at the
evaluator results, so it comes after evaluate_and_refine. Return JSON only
with keys:
steps (list of objects with tool and purpose), and reasoning (one sentence
on why this order).
""".strip()
    plan = call_llm_json(
        "planning_agent",
        system_prompt,
        {
            "symbol": symbol,
            "available_tools": PLAN_TOOLS,
            "past_notes": notes or [],
        },
        lambda: fallback_research_plan(symbol),
    )

    # drop any step that uses a tool we don't have
    steps = plan.get("steps", [])
    valid = [
        s for s in steps if isinstance(s, dict) and s.get("tool") in PLAN_TOOLS
    ]
    if valid:
        plan["steps"] = valid
    else:
        plan.update(fallback_research_plan(symbol))
        plan["decision_source"] = "deterministic_fallback"

    # the plan always has to read memory, self-reflect and write memory,
    # even if the LLM left them out
    tools = [s["tool"] for s in plan["steps"]]
    if "read_memory" not in tools:
        plan["steps"].insert(
            0, {"tool": "read_memory", "purpose": "Check notes from past runs"}
        )
    if "write_memory" not in tools:
        plan["steps"].append(
            {"tool": "write_memory", "purpose": "Save what we learned"}
        )
    if "self_reflect" not in tools:
        tools = [s["tool"] for s in plan["steps"]]
        plan["steps"].insert(
            tools.index("write_memory"),
            {"tool": "self_reflect", "purpose": "Save lessons from this run"},
        )

    plan["symbol"] = symbol
    log_memory_event("plan", plan)
    return plan

Agent Design and Workflows. The planner is one LLM call that picks from a fixed list of tools. It can reorder steps or drop them, but it can't make up new ones. Reading memory, self-reflection and writing memory always stay in the plan.

Agent Functions and Capabilities. Given a stock symbol and any notes from past runs, it returns an ordered list of steps with a reason for each. The end to end function in section 10 runs the steps in that order, and the planner is asked again if the news for the symbol comes back empty.

Evaluation and Iteration. Any step with a tool name we don't have gets thrown out. If nothing usable is left, it falls back to a default order, so a bad LLM answer can't break the run. The output shows whether the plan came from the LLM or the fallback.

NOTES_PATH = MEMORY_DIR / "research_notes.jsonl"


def read_memory(symbol, limit=3):
    # return the most recent notes saved for this symbol
    if not NOTES_PATH.exists():
        return []
    notes = []
    with NOTES_PATH.open(encoding="utf-8") as f:
        for line in f:
            try:
                note = json.loads(line)
            except json.JSONDecodeError:
                continue
            if note.get("symbol") == symbol.upper():
                notes.append(note)
    return notes[-limit:]


def memory_context(symbols):
    # short lines the agents can read, empty list if nothing is saved yet
    lines = []
    for symbol in symbols:
        for note in read_memory(symbol):
            line = f"{symbol} ({note['run_id']}): {note['note']}"
            if note.get("open_question"):
                line += f" Still open: {note['open_question']}"
            lines.append(line)
    return lines

    params = {

def ingest_from_yahoo_finance_rss(tickers=None, limit=10):
    tickers = tickers or ["AAPL", "MSFT", "NVDA", "TSLA", "JPM"]
    ticker_query = ",".join(tickers)
    url = (
        "https://feeds.finance.yahoo.com/rss/2.0/headline"
        f"?s={ticker_query}&region=US&lang=en-US"
    )
    request = Request(
        url, headers={"User-Agent": "financial-prompt-chain-notebook"}
    )
    with urlopen(request, timeout=20) as response:
        xml_text = response.read().decode("utf-8", errors="ignore")
    root = ET.fromstring(xml_text)
    articles = []
    for item in root.findall(".//item"):
        title = item.findtext("title") or ""
        description = item.findtext("description") or ""
        published_at = item.findtext("pubDate") or ""
        url = item.findtext("link") or ""
        if title or description:
            articles.append(
                NewsArticle(
                    title=title,
                    description=description,
                    source="Yahoo Finance RSS",
                    published_at=published_at,
                    url=url,
                )
            )
        if len(articles) >= limit:
            break
    return articles

def clean_text(value):
    value = unescape(value or "")
    value = value.replace("�", "'")
    value = re.sub(r"https?://\S+", " ", value)
    value = re.sub(r"<[^>]+>", " ", value)
    value = re.sub(r"\s+", " ", value)
    return value.strip()


def preprocess_articles(articles):
    processed = []
    seen = set()
    for index, article in enumerate(articles, start=1):
        title = clean_text(article.title)
        description = clean_text(article.description)
        combined = f"{title}. {description}".strip()
        fingerprint = re.sub(r"[^a-z0-9]+", "", combined.lower())[:180]
        if not combined or fingerprint in seen:
            continue
        seen.add(fingerprint)
        processed.append(
            ProcessedArticle(
                id=len(processed) + 1,
                title=title,
                text=combined,
                source=article.source,
                published_at=article.published_at,
                url=article.url,
            )
        )
    return processed

def fallback_classification(article):
    text = article.text.lower()
    scores = {
        label: sum(1 for keyword in keywords if keyword in text)
        for label, keywords in CLASS_KEYWORDS.items()
    }
    label, score = max(scores.items(), key=lambda item: item[1])
    if score == 0:
        label = "general_financial_news"
    confidence = min(0.95, 0.45 + (score * 0.15)) if score else 0.35
    return {
        "label": label,
        "confidence": round(confidence, 2),
        "rationale": f"Keyword evidence: {scores}",
        "scores": scores,
    }

def fallback_extract_signals(item):
    article = item["article"]
    text = article["text"]
    lower_text = text.lower()
    tickers = sorted(
        {
            ticker
            for company, ticker in COMPANY_TO_TICKER.items()
            if company in lower_text
        }
    )
    explicit_tickers = re.findall(r"\b[A-Z]{2,5}\b", text)
    tickers = sorted(
        set(
            tickers
            + [
                ticker
                for ticker in explicit_tickers
                if ticker not in TICKER_STOPWORDS
            ]
        )
    )

    words = re.findall(r"[a-zA-Z]+", lower_text)
    positive_hits = [word for word in words if word in POSITIVE_TERMS]
    negative_hits = [word for word in words if word in NEGATIVE_TERMS]
    sentiment_score = len(positive_hits) - len(negative_hits)
    sentiment = (
        "positive"
        if sentiment_score > 0
        else "negative" if sentiment_score < 0 else "neutral"
    )

    catalysts = sorted(term for term in CATALYST_TERMS if term in lower_text)
    risks = sorted(term for term in RISK_TERMS if term in lower_text)
    return {
        "tickers": tickers,
        "sentiment": sentiment,
        "sentiment_score": sentiment_score,
        "positive_terms": positive_hits,
        "negative_terms": negative_hits,
        "catalysts": catalysts,
        "risks": risks,
        "investment_implication": "Signal from the rule-based fallback.",
    }

def fallback_summarize_signals(signals):

    by_sentiment = Counter(signal["sentiment"] for signal in signals)
    ticker_counts = Counter(
        ticker for signal in signals for ticker in signal["tickers"]
    )
    catalysts = Counter(
        catalyst for signal in signals for catalyst in signal["catalysts"]
    )
    risks = Counter(risk for signal in signals for risk in signal["risks"])
    specialists = Counter(
        signal.get("specialist", "not_routed") for signal in signals
    )
    market_sources = Counter(
        data.get("source", "unknown")
        for signal in signals
        for data in signal.get("market_data", {}).values()
    )

    top_items = sorted(
        signals,
        key=lambda signal: (
            abs(signal["sentiment_score"]),
            signal["class_confidence"],
        ),
        reverse=True,
    )
    brief = []
    brief.append("Financial News Prompt-Chain Brief")
    brief.append("=" * 36)
    brief.append(f"Articles analyzed: {len(signals)}")
    brief.append(f"Content mix: {dict(by_class)}")
    brief.append(f"Sentiment mix: {dict(by_sentiment)}")
    top_tickers = dict(ticker_counts.most_common(5)) or "none detected"
    top_catalysts = dict(catalysts.most_common(5)) or "none detected"
    brief.append(f"Most mentioned tickers: {top_tickers}")
    brief.append(f"Leading catalysts: {top_catalysts}")
    brief.append(
        f"Leading risks: {dict(risks.most_common(5)) or 'none detected'}"
    )
    if any(signal.get("specialist") for signal in signals):
        brief.append(f"Specialist routing: {dict(specialists)}")
    if market_sources:
        brief.append(f"Market data sources: {dict(market_sources)}")
    brief.append("")
    brief.append("Key article-level takeaways:")
    for signal in top_items:
        ticker_text = (
            ", ".join(signal["tickers"])
            if signal["tickers"]
            else "broad market"
        )
        catalyst_text = (
            ", ".join(signal["catalysts"])
            if signal["catalysts"]
            else "no explicit catalyst"
        )
        risk_text = (
            ", ".join(signal["risks"])
            if signal["risks"]
            else "no major risk term"
        )
        specialist_text = (
            f" | specialist={signal['specialist']}"
            if signal.get("specialist")
            else ""
        )
        implication = (
            f" | implication={signal['investment_implication']}"
            if signal.get("investment_implication")
            else ""
        )
        brief.append(
            f"- {signal['title']} | class={signal['class']} | "
            f"tickers={ticker_text}{specialist_text} | "
            f"sentiment={signal['sentiment']} | catalysts={catalyst_text} | "
            f"risks={risk_text}{implication}"
        )
    return "\n".join(brief)

Agent Design and Workflows. Prompt chaining here is five stages in a fixed order: ingest, preprocess, classify, extract and summarize. Each stage takes the output of the one before it, so a problem in one stage shows up in the next one's input. Classify and extract are LLM agents. Ingest, preprocess and summarize are plain code.

Agent Functions and Capabilities. Ingest tries NewsAPI first, limited to finance sites, and retries without the filter if that finds nothing. It then uses the bundled CSV, then built-in sample articles. Preprocess cleans and deduplicates. Classify gives each article one of five labels with a confidence. Extract lists tickers, sentiment, catalysts and risks, and only lists a ticker when the article names the company or the ticker itself. The summary and the run record are saved to memory.

Evaluation and Iteration. If the LLM is not available, classify and extract use keyword rules, and the output shows which one was used. A list of words that look like tickers but are not (ETF, CEO, GDP and so on) is removed from the extracted tickers. The run report shows stage completion, record counts and the tickers found, so each stage can be checked.

def load_market_data_from_csv(path=DEFAULT_MARKET_CSV):
    market_data = {}
    if not os.path.exists(path):
        return market_data
    with open(path, newline="", encoding="utf-8") as f:
        reader = csv.DictReader(f)
        for row in reader:
            ticker = row.get("ticker", "").upper()
            if not ticker:
                continue
            market_data[ticker] = {
                "ticker": ticker,
                "company": row.get("company", ""),
                "current_price": float(row.get("current_price") or 0),
                "previous_close": float(row.get("previous_close") or 0),
                "one_month_return": float(row.get("one_month_return") or 0),
                "average_volume": int(float(row.get("average_volume") or 0)),
                "market_cap": int(float(row.get("market_cap") or 0)),
                "trailing_pe": float(row.get("trailing_pe") or 0),
                "source": row.get("source", "bundled_sample"),
            }
    return market_data

def fetch_yfinance_market_data(tickers):
    try:
        import yfinance as yf
    except Exception:
        return {}

    live_data = {}
    for ticker in tickers:
        try:
            asset = yf.Ticker(YAHOO_SYMBOLS.get(ticker, ticker))
            history = asset.history(period="1mo")
            if history.empty:
                continue
            # name, market cap and P/E come from a separate call that can
            # fail on its own, so the price data still works without it
            try:
                info = asset.info or {}
            except Exception:
                info = {}
            current_price = float(history["Close"].iloc[-1])
            previous_close = (
                float(history["Close"].iloc[-2])
                if len(history) > 1
                else current_price
            )
            first_close = float(history["Close"].iloc[0])
            one_month_return = (
                (current_price - first_close) / first_close
                if first_close
                else 0
            )
            live_data[ticker] = {
                "ticker": ticker,
                "company": info.get("shortName") or ticker,
                "current_price": round(current_price, 2),
                "previous_close": round(previous_close, 2),
                "one_month_return": round(one_month_return, 4),
                "average_volume": (
                    int(history["Volume"].mean()) if "Volume" in history else 0
                ),
                "market_cap": int(info.get("marketCap") or 0),
                "trailing_pe": round(float(info.get("trailingPE") or 0), 2),
                "source": "yfinance",
            }
        except Exception:
            continue
    return live_data


def get_market_context(tickers):
    tickers = sorted(set(tickers))
    fallback_data = load_market_data_from_csv()
    live_data = fetch_yfinance_market_data(tickers)
    return {
        ticker: live_data.get(ticker)
        or fallback_data.get(
            ticker, {"ticker": ticker, "source": "not_available"}
        )
        for ticker in tickers
    }

Agent Design and Workflows. Tool use means the agent gets its data from outside tools instead of from the model's memory: news from NewsAPI and Yahoo Finance RSS, and prices from yfinance. The planner in section 2 decides when these tools run.

Agent Functions and Capabilities. The real news test runs the prompt chain on live Yahoo Finance RSS headlines. The yfinance step adds the current price, one-month return, volume, market cap and P/E for each ticker found, and the specialists use these numbers in their analysis. Indian tickers such as HDFCBANK and ICICIBANK are mapped to their .NS symbols so yfinance can find them.

Evaluation and Iteration. The real news test checks that articles came back, that every stage kept the same article count, and that the summary is long enough to be useful. If yfinance has nothing for a ticker, the bundled market data CSV is used, and a ticker in neither is marked not_available so the analysis never makes up numbers.

6. Workflow Pattern: Routing¶

Routing sends each article to the most relevant specialist based on the article class produced earlier in the chain. This mimics an agentic system where a coordinator chooses the right expert for each task.

def fallback_route(signal):
    # no LLM, so map the class from the chain straight to a specialist
    return {
        "specialist": CLASS_TO_SPECIALIST.get(signal["class"], "market"),
        "reasoning": f"Mapped from class: {signal['class']}",
    }


def route_signal(signal):
    system_prompt = """
You are a routing agent for a financial research team. Read one article
signal and pick the specialist who should analyze it. Choose exactly one
of: earnings, macro, market, company_news. suggested_specialist comes from
the article class. Only pick a different specialist if the content clearly
belongs there, and say why. Return JSON only with keys: specialist,
reasoning (one sentence), and confidence (number from 0 to 1).
""".strip()
    keys = ("title", "class", "tickers", "sentiment", "catalysts", "risks")
    suggested = fallback_route(signal)["specialist"]
    result = call_llm_json(
        "routing_agent",
        system_prompt,
        {
            "specialists": list(SPECIALISTS),
            "suggested_specialist": suggested,
            "signal": {key: signal[key] for key in keys},
        },
        lambda: fallback_route(signal),
    )
    result["table_pick"] = suggested
    result["override_rejected"] = False
    if result.get("specialist") not in SPECIALISTS:
        # the LLM made up a specialist, use the default mapping instead
        result.update(fallback_route(signal))
        result["decision_source"] = "deterministic_fallback"
    elif result["specialist"] != suggested:
        # changing the table's pick needs high confidence, or we keep it
        try:
            confident = float(result.get("confidence", 0)) >= 0.8
        except (TypeError, ValueError):
            confident = False
        if not confident:
            result["reasoning"] = (
                "Kept the table pick, the override was not confident. "
                + result.get("reasoning", "")
            )
            result["specialist"] = suggested
            result["override_rejected"] = True
    return result


def fallback_specialist_analysis(signal):
    risks = ", ".join(signal["risks"]) or "no major risk terms"
    return {
        "analysis": (
            f"{signal['title']}. Sentiment is {signal['sentiment']} "
            f"with {risks}."
        ),
        "key_points": signal["catalysts"],
        "confidence": 0.4,
    }


def run_specialist(signal, specialist, notes):
    system_prompt = f"""
{SPECIALISTS[specialist]}
Write the analysis from the signal, market_data and past_notes only. Do not
add facts, numbers or tickers that are not in them. Name the ticker(s), or
say the article is about the broad market or a sector if there are none.
Explain what is driving the news. Name at least one risk, or say the signal
lists none. If market_data has prices, quote the price or the one-month
return.
Analyze the article signal. If past_notes are given, end the analysis with
one sentence on how this article compares to them: does it confirm them,
contradict them, or add something new. Return JSON only with keys: analysis
(2 to 3 sentences, plus the comparison sentence if there are notes),
key_points (list of short strings), confidence (number from 0 to 1), and
used_notes (one sentence on how the past notes changed your view, or
"none").
""".strip()
    return call_llm_json(
        f"{specialist}_specialist",
        system_prompt,
        {"signal": signal, "past_notes": notes},
        lambda: fallback_specialist_analysis(signal),
    )


def route_articles(signals):
    routed = []
    for signal in signals:
        route = route_signal(signal)
        specialist = route["specialist"]

        item["specialist"] = specialist
        item["routing_reason"] = route.get("reasoning", "")
        item["routing_source"] = route.get("decision_source", "unknown")
        item["specialist_analysis"] = run_specialist(signal, specialist, notes)
        routed.append(item)
    return routed

7. Workflow Pattern: Evaluator-Optimizer¶

Each specialist analysis from section 6 is scored by an evaluator agent against a five-point rubric. If it scores below the pass mark, an optimizer agent rewrites it using the evaluator's feedback, and the rewrite is scored again. This repeats until the analysis passes or the round limit is reached. A self-reflection agent then looks at the whole run and saves lessons for the next one.

This section uses LangChain for the agents and LangGraph for the evaluate → refine loop. Like the rest of the notebook, every agent has a deterministic fallback, so the section still runs without an API key.

def has_market_data(item):
    # true only if at least one ticker has real price data
    # (a ticker whose source is "not_available" doesn't count)
    return any(
        d.get("source") != "not_available"
        for d in item.get("market_data", {}).values()
    )


def _long_words(text):
    # meaningful words only (5+ letters), used to compare the analysis with
    # catalysts and risks
    return {w for w in re.findall(r"[a-z]+", text.lower()) if len(w) > 4}


def fallback_evaluate(item, analysis):
    # rule-based grading used when there's no LLM.
    # it checks the analysis TEXT, so a better rewrite gets a better score
    text = analysis.lower()
    words = set(re.findall(r"[a-z]+", text))
    scores, feedback = {}, []

    # names_tickers: does the analysis mention the stock(s) from the article?
    tickers = item.get("tickers", [])
    scores["names_tickers"] = (
        1.0 if not tickers or any(t.lower() in text for t in tickers) else 0.0
    )
    if scores["names_tickers"] < 1:
        feedback.append(f"Name the ticker(s): {', '.join(tickers)}")

    # covers_catalysts: does it share a key word with the extracted catalysts?
    catalyst_words = _long_words(" ".join(item.get("catalysts", [])))
    scores["covers_catalysts"] = (
        1.0
        if not catalyst_words or catalyst_words & _long_words(text)
        else 0.0
    )
    if scores["covers_catalysts"] < 1:
        feedback.append("Explain the catalyst behind the move")

    # covers_risks: does it mention an extracted
    # risk, or at least the word "risk"?
    risk_words = _long_words(" ".join(item.get("risks", []))) | {
        "risk",
        "risks",
    }
    scores["covers_risks"] = 1.0 if risk_words & words else 0.0
    if scores["covers_risks"] < 1:
        feedback.append("Name at least one risk")

    # uses_market_data: if real price data exists,
    # the analysis should quote a number
    if has_market_data(item):
        scores["uses_market_data"] = 1.0 if re.search(r"\d", analysis) else 0.0
        if scores["uses_market_data"] < 1:
            feedback.append(
                "Add the price or one-month return from market_data"
            )
    else:
        scores["uses_market_data"] = 1.0

    # rules can't fact-check, so grounding gets a neutral score without the LLM
    scores["grounded"] = 0.7
    return {"scores": scores, "feedback": feedback}


def evaluate_analysis(item, analysis, lessons=()):
    # everything the evaluator needs to judge the
    # analysis: the rubric, the text,
    # the facts it should be based on, past notes on
    # these tickers, and earlier lessons
    payload = {
        "rubric": RUBRIC,
        "analysis": analysis,
        "signal": {key: item.get(key) for key in SIGNAL_KEYS},
        "market_data": item.get("market_data", {}),
        "past_notes": memory_context(item.get("tickers", [])),
        "lessons_from_earlier_runs": list(lessons),
    }
    # ask claude for an Evaluation (or use the fallback if that's not possible)
    result = run_structured(
        "evaluator_agent",
        EVALUATOR_PROMPT,
        Evaluation,
        {"payload": json.dumps(payload, indent=2, default=str)},
        lambda: fallback_evaluate(item, analysis),
    )
    # clamp each score to 0..1 and average them
    # ourselves instead of trusting the LLM
    scores = {}
    for key in RUBRIC:
        try:
            scores[key] = max(
                0.0, min(1.0, float(result.get("scores", {}).get(key, 0)))
            )
        except (TypeError, ValueError):
            scores[key] = 0.0
    # feedback should always be a list, even if something else came back
    feedback = result.get("feedback") or []
    if not isinstance(feedback, list):
        feedback = [str(feedback)]
    overall = round(sum(scores.values()) / len(scores), 2)
    # one result shape for both paths, including the pass/fail decision
    return {
        "scores": scores,
        "overall": overall,
        "passed": overall >= QUALITY_THRESHOLD,
        "feedback": feedback,
        "decision_source": result["decision_source"],
    }

def fallback_refine(item, analysis, evaluation):
    # no LLM: add a sentence for each rubric item
    # the evaluator marked as missing
    scores = evaluation["scores"]
    extra = []
    if scores["names_tickers"] < 1 and item.get("tickers"):
        extra.append(f"Tickers: {', '.join(item['tickers'])}.")
    if scores["covers_catalysts"] < 1 and item.get("catalysts"):
        extra.append(f"Main catalyst: {item['catalysts'][0]}.")
    if scores["covers_risks"] < 1:
        risk = (
            item["risks"][0]
            if item.get("risks")
            else "no clear risk is named in the article"
        )
        extra.append(f"Key risk: {risk}.")
    if scores["uses_market_data"] < 1:
        # quote price and one-month return for every ticker that has real data
        for ticker, data in item.get("market_data", {}).items():
            if data.get("source") != "not_available":
                extra.append(
                    f"{ticker} trades at ${data.get('current_price', 0):.2f}, "
                    f"{data.get('one_month_return', 0) * 100:+.1f}% over "
                    "one month."
                )
    return {
        "analysis": " ".join([analysis] + extra),
        "changes": [f"Added: {e}" for e in extra],
    }

    # may use, and earlier lessons

        "analysis": analysis,
        "feedback": evaluation["feedback"],
        "signal": {key: item.get(key) for key in SIGNAL_KEYS},
        "market_data": item.get("market_data", {}),
        "lessons_from_earlier_runs": list(lessons),

    )
    # keep the old text if the rewrite came back empty
    result["analysis"] = (result.get("analysis") or "").strip() or analysis
    return result

The evaluate → refine loop¶

The loop is a small LangGraph graph. The evaluate node scores the current draft. A conditional edge then either ends the loop or sends it to the refine node, which rewrites it and sends it back to evaluate. Every round is added to history, so each article keeps its full score trail. When the loop ends, the highest-scoring draft is kept rather than the last one, because a rewrite can score lower than the draft before it. The function is called 'evaluate_and_refine', the same name as the planner's tool in section 2.

# the evaluate -> refine loop as a langgraph graph,
# then run it on every routed article


# graph state: the data every node can read. Each
# node returns only the fields it changed
class EvalState(TypedDict):
    item: dict  # one routed article from section 6
    analysis: str  # current draft
    evaluation: dict  # latest evaluator result
    history: Annotated[
        list, operator.add
    ]  # each round is appended, never overwritten


def evaluate_node(state):
    # node 1: score the current draft and record this round in the history
    evaluation = evaluate_analysis(
        state["item"], state["analysis"], past_lessons
    )
    entry = {
        "round": len(state["history"]) + 1,
        "overall": evaluation["overall"],
        "scores": evaluation["scores"],
        "feedback": evaluation["feedback"],
        "analysis": state["analysis"],
        "source": evaluation["decision_source"],
    }
    return {"evaluation": evaluation, "history": [entry]}


def refine_node(state):
    # node 2: rewrite the draft using the latest feedback
    refined = refine_analysis(
        state["item"], state["analysis"], state["evaluation"], past_lessons
    )
    return {"analysis": refined["analysis"]}


def after_evaluate(state):
    # conditional edge: stop when the draft passes or the round budget is used
    # up, otherwise refine
    if state["evaluation"]["passed"] or len(state["history"]) >= MAX_ROUNDS:
        return "done"
    return "refine"


# wire the graph: START -> evaluate -> (done: END | refine)
# and refine -> evaluate
builder = StateGraph(EvalState)
builder.add_node("evaluate", evaluate_node)
builder.add_node("refine", refine_node)
builder.add_edge(START, "evaluate")
builder.add_conditional_edges(
    "evaluate", after_evaluate, {"refine": "refine", "done": END}
)
builder.add_edge("refine", "evaluate")  # the back-edge that makes it a loop
eval_graph = builder.compile()


def evaluate_and_refine(item):
    # run the graph for one article, starting from
    # the specialist's first draft.
    # the recursion limit is a second safety cap on top of MAX_ROUNDS
    final = eval_graph.invoke(
        {
            "item": item,
            "analysis": item.get("specialist_analysis", {}).get(
                "analysis", ""
            ),
            "evaluation": {},
            "history": [],
        },
        config={"recursion_limit": 2 * MAX_ROUNDS + 2},
    )
    # copy the article and add the results, so later
    # sections get everything in one dict
    history = final["history"]
    # keep the highest-scoring draft, not the last one: a rewrite can score
    # lower than the draft before it (on a tie, the earlier draft is kept)
    best = max(history, key=lambda h: h["overall"])
    result = dict(item)
    result["final_analysis"] = best["analysis"]
    result["eval_history"] = history
    result["first_score"] = history[0]["overall"]
    result["final_score"] = best["overall"]
    result["best_round"] = best["round"]
    result["rounds"] = len(history)
    result["passed"] = best["overall"] >= QUALITY_THRESHOLD
    return result

Design. The evaluator, optimizer and self-reflection agents are LangChain chains: a 'ChatPromptTemplate' piped into 'ChatAnthropic.with_structured_output(...)', so each answer has to match a Pydantic schema ('Evaluation', 'Refinement', 'Reflection') instead of being pulled out of free text. The loop is a LangGraph 'StateGraph' with two nodes ('evaluate' and 'refine'), a conditional edge that decides whether to stop, and a back-edge from 'refine' to 'evaluate'. The optimizer reuses the specialist role prompts from section 6. If there's no API key, or a call fails, each agent uses a rule-based fallback and logs an 'llm_error' event, like the rest of the notebook.

Capabilities. Every specialist analysis is scored on five criteria (grounded, names tickers, covers catalysts, covers risks, uses market data) and gets specific fixes. Weak analyses are rewritten and scored again, up to 'MAX_ROUNDS' evaluations. Each article keeps its full score history, first and final scores, which round's draft was kept, and whether it passed. The kept draft is always the highest-scoring one, so refinement can't leave an analysis worse than it started. Self-reflection turns the run's repeated feedback into lessons. The next run loads them, and the evaluator and optimizer check them.

Evaluation and iteration. The first version of the fallback evaluator checked the article's extracted signal instead of the analysis text, so a rewrite could never change its score. It now checks the text. The market-data check also used to count a ticker marked 'not_available' as having data, and now it doesn't. The overall score is averaged in code from bounded 0 to 1 scores, so a malformed LLM score can't break the pass/fail decision. An earlier live run showed another problem: the loop kept the last draft even when a rewrite scored lower, and in the worst case an analysis fell from 0.62 to 0.30 after the optimizer stripped it down to satisfy feedback about unsupported claims. The loop now keeps the highest-scoring draft from each article's history. In the latest live run with Claude Haiku on 25 articles, 19 analyses passed on the first check and 6 were refined. 4 of those reached the 0.8 pass mark (3 after one rewrite, 1 after two), passing 23 of 25 overall, and the average score rose from 0.87 to 0.90. The other 2 hit the 3-round limit. In both, a later rewrite scored lower than an earlier draft (down to 0.52 and 0.54), so the loop kept the best draft, round 1 for one article and round 2 for the other. Without an LLM, the lessons are saved and loaded but don't change any scores, because only the LLM agents read them.

Agent Design and Workflows. At the end of a run, a memory agent compares the new signals to the past notes and writes one or two sentences per stock: the main driver, the main risk, and anything uncertain. It also saves one open question, the main thing still unresolved. If the new signals only repeat the past notes, no new note is saved. If the LLM isn't available, a fallback note counts the sentiment and lists the risks.

Agent Functions and Capabilities. These notes are what the next run reads back, so each run starts with what the last one learned. The planner and the specialists both get them, including the open question. Lessons from self-reflection go to the evaluator and the optimizer instead.

Evaluation and Iteration. The demo above runs one specialist twice on the same article, once without notes and once with them. With notes, the analysis ends by saying whether the article confirms, contradicts, or adds to what was saved. Saving a note again in the same run replaces the old one instead of adding a duplicate. Only the LLM reads the notes, so the rule-based fallback gives the same answer both times. The lessons check below takes the weak first drafts from section 7, lets the optimizer rewrite each one without and with the saved lessons, and scores both rewrites with the evaluator from section 7.

def run_planned_workflow(symbol, limit=10):
    state = {
        "symbol": symbol.upper(),
        "limit": limit,
        "done": [],
        "ran_early": [],
        "skipped": [],
        "replans": [],
    }
    # read what we learned about this symbol on past runs, then plan
    state["notes"] = memory_context([state["symbol"]])
    plan = plan_research(state["symbol"], notes=state["notes"])

    def run_step(tool, needed_by=None):
        if tool in state["done"]:
            return
        if tool in STEP_NEEDS:
            run_step(STEP_NEEDS[tool], needed_by=tool)
        if needed_by:
            state["ran_early"].append(f"{tool} (needed by {needed_by})")
        if tool not in STEP_FUNCTIONS:
            # a planned tool with no step function is skipped
            if tool not in state["skipped"]:
                state["skipped"].append(tool)
            return
        STEP_FUNCTIONS[tool](state)
        state["done"].append(tool)

    # run the steps in the order the planner picked
    steps = list(plan["steps"])
    position = 0
    while position < len(steps):
        run_step(steps[position]["tool"])
        position += 1
        if state.get("news_missing") and not state["replans"]:
            # no news for this symbol, ask the planner for a new plan
            state["news_missing"] = False
            warning = (
                f"No news found for {state['symbol']}, "
                "using the general news feed instead."
            )
            new_plan = plan_research(
                state["symbol"], notes=state["notes"] + [warning]
            )
            state["replans"].append(new_plan.get("reasoning", ""))
            remaining = [
                s for s in new_plan["steps"] if s["tool"] not in state["done"]
            ]
            steps = steps[:position] + remaining

    if state.get("routed"):
        state["summary"] = summarize_signals(state["routed"])
    # evaluator results: average first and final
    # scores, rounds, and how many passed
    evaluated = [s for s in state.get("routed", []) if "final_analysis" in s]
    if evaluated:
        count = len(evaluated)
        state["evaluation"] = {
            "articles": count,
            "avg_first_score": round(
                sum(s["first_score"] for s in evaluated) / count, 2
            ),
            "avg_final_score": round(
                sum(s["final_score"] for s in evaluated) / count, 2
            ),
            "avg_rounds": round(
                sum(s["rounds"] for s in evaluated) / count, 2
            ),
            "passed": sum(s["passed"] for s in evaluated),
        }
    state["plan"] = plan
    # same keys the original end to end function returned
    state["raw_count"] = len(state.get("raw", []))
    state["processed_count"] = len(state.get("processed", []))
    state["extracted_signals"] = state.get("signals", [])
    state["routed_signals"] = state.get("routed", [])
    log_memory_event(
        "research_run",
        {
            "symbol": state["symbol"],
            "plan_source": plan.get("decision_source"),
            "steps_run": state["done"],
            "skipped": state["skipped"],
            "replans": len(state["replans"]),
            "evaluation": state.get("evaluation"),
            "lessons": len(state.get("reflection", {}).get("lessons", [])),
        },
    )
    return state

Agent Design and Workflows. run_agentic_workflow runs the full prompt chain and the evaluator on every article. run_planned_workflow ties every section together for one symbol. It reads past notes, asks the planner for a plan, then runs the plan one step at a time. Each step reads from and writes to one shared "state" dictionary. After the chain runs, only articles that mention the symbol (by ticker or company name) are kept, and the output says how many matched. If a step needs something that has not run yet, the earlier step runs first and gets listed under "Ran early". A planned step with no code behind it is skipped and listed under "Skipped".

Agent Functions and Capabilities. The agent plans per symbol, picks and orders its own tools, uses past notes, routes each article to a specialist, evaluates and refines each analysis, reflects on the run and saves lessons, and saves a new note at the end so the next run can build on it. The news for the symbol comes from Yahoo Finance RSS and NewsAPI. If no news is found for the symbol, the planner is asked for a new plan and the run continues with it.

Evaluation and Iteration. The output prints whether the plan came from the LLM or the fallback, the order the steps ran, anything that ran early or was skipped, whether the run re-planned, how many articles are about the symbol, the evaluator's average score before and after refinement, and the lessons the agent saved. Running the same symbol again shows the memory effect, because the second run reads the notes and lessons saved by the first.

11. Why These Workflow Patterns Matter¶

This project uses prompt chaining to break financial analysis into smaller, reliable steps instead of asking one model or function to do everything at once. Each stage produces structured output that becomes the input for the next stage.

Chain Step Purpose Output
Ingest News Pull financial news from NewsAPI, Yahoo RSS, or sample data Raw articles
Preprocess Clean, normalize, and deduplicate article text Clean article records
Classify Identify the type of financial content Earnings, macro, market movement, company news
Extract Pull investment signals from each article Tickers, sentiment, catalysts, risks
Summarize Convert extracted signals into a research brief Final financial news summary

Separating the workflow this way makes the system easier to debug, evaluate, and improve. If one stage produces weak results, that stage can be refined without rewriting the entire pipeline.

Routing does the same thing for the analysis step. One prompt trying to analyze everything gives generic answers, so each article goes to a specialist with its own focus. The router starts from the article class and only changes it when it is confident (0.8 or higher) the content belongs somewhere else. If the LLM isn't available, a lookup table is used.

Specialist What it looks at Article classes it covers Example article
Earnings Results vs estimates, guidance, margins earnings A bank beats earnings estimates
Macro Rates, inflation, central bank signals macro Central bank signals caution on rate cuts
Market Price moves, analyst sentiment, momentum market_movement, general_financial_news A chip stock rises on analyst forecasts
Company news Products, supply chain, deals, legal issues company_news A supplier report on slower phone orders

Each routed article keeps a "routing_reason" and "routing_source", so we can see why it went where it did. The routing check in section 6 counts how often the router agrees with the class table on real news. The table mostly decides, and the router is a safety check with a high bar.

The evaluator-optimizer adds a quality check after the specialists. A specialist's first draft can be vague or miss the numbers, so an evaluator agent scores it against a rubric and an optimizer agent rewrites it until it passes or runs out of rounds. Separating writing from grading makes the grade a to-do list instead of just a number, and every article keeps its score history, so you can see exactly what improved.

Rubric item What the evaluator checks Fallback check (no API key)
Grounded Every claim is backed by the signal, market data or past notes Neutral 0.7, rules can't fact-check
Names tickers The stock(s) are named, or it says broad market A ticker appears in the text
Covers catalysts Explains what is driving the move Shares a key word with the extracted catalysts
Covers risks Names at least one risk Mentions an extracted risk or the word "risk"
Uses market data Quotes price or return when data exists Contains a number when market data is available

An analysis passes at an average of 0.8, with at most 3 evaluations. After the loop, a self-reflection agent saves up to three lessons from the run's feedback, and the next run's evaluator and optimizer check them.

Why the two failures happened. Both are market commentary pieces, and the extractor found no tickers in either, so there was no market data to quote. That alone is not the cause, because many macro articles also have no tickers and still pass (the September CPI article scored 0.99). Those articles name concrete events and numbers, such as CPI at 3.7% and Brent above $102. The Cramer and used car articles give general advice and name no concrete event, so the analysis has little to be grounded in. Rewriting did not fix that. In the Cramer analysis the risk stayed general (market unpredictability and volatility). In the used car analysis the kept draft brings in short strangles, policy shifts affecting financing and a demand collapse, which appear to go beyond what the article's signal supports, and the third draft fell to 0.54. The saved outputs do not print the score for each criterion for these two articles, so we cannot say which criteria dropped. The pattern still fits what we see: when the article gives the writer nothing concrete, the evaluator asks for specifics, and the optimizer either repeats general statements or adds content that is not in the signal. The grounding lessons that self-reflection saves point the same way: stay with the signal, and say so when it lists no catalysts.

Reading the lessons result honestly. The lessons check uses 6 articles. The lessons were written from feedback in earlier runs, and some of the same articles may appear again, so the check is not fully held out, in the same way a model should not be tested on the data it was fit on (Jurafsky & Martin, 2025). The result is within noise, and we report it as that.

Link to the course ideas. Prompt chaining, routing and evaluator-optimizer are three of the workflow patterns described by Schluntz and Zhang (2024), where the code decides the path. The planner is closer to an agent because the LLM chooses the order of tools, which follows the plan-then-act idea in ReAct (Yao et al., 2023). The refine loop follows Self-Refine (Madaan et al., 2023), and the lessons follow Reflexion (Shinn et al., 2023). The notes are read back by ticker, which is a simple form of retrieval. Retrieval-augmented generation (Lewis et al., 2020) would be the next step for larger memory.

13. Limitations¶

  • The evaluator is an LLM. The same model family writes and scores the analyses, and LLM judges can favor their own style (Zheng et al., 2023). A score of 0.9 means the evaluator is satisfied, not that a person would agree.
  • Scores check grounding, not truth. The evaluator compares the analysis to the extracted signal. It does not check whether the news is correct or whether the stock will move as described. Nothing here is investment advice, and the system has not been backtested.
  • Small and changing samples. Each run uses 25 articles and the lessons check uses 6. News changes between runs, the LLM is not deterministic, and no significance test was run, so small differences, like the 0.02 from lessons, should not be read as real.
  • Hard cases remain. Opinion and commentary articles, with few tickers and few catalysts, still fail the 0.8 mark, and rewriting can lower their scores.
  • Lessons are free text. They can conflict with each other, for example "name catalysts" and "say when there are none". For that reason they go only to the evaluator and optimizer, not to the specialists, and they are capped at 5.
  • Data coverage. News comes from headlines and short descriptions, not full articles. NewsAPI has plan limits, and yfinance is an unofficial source that can fail or rate limit. When it does, the bundled CSV is used and a ticker with no data is marked not_available.
  • Memory is files in the Colab runtime. Resetting the runtime deletes the notes and lessons, so the learning across runs only holds inside one session unless the folder is saved elsewhere.
  • Fallbacks are weak. Without an LLM, the keyword classifier, rule-based extractor and rule-based evaluator keep the notebook running, but they do not read lessons and give much weaker analysis.
  • Cost and speed. Each article takes several sequential LLM calls (classify, extract, route, write, evaluate, and up to two rewrites), so large portfolios would be slow and costly.

14. Future Improvements¶

  • Use a different judge. Score with a stronger or different model, or with several judges, and compare with a small set of analyses that people have rated, so the evaluator can be calibrated (Zheng et al., 2023).
  • Handle commentary articles. Change the rubric so that articles with no company or catalyst are not penalized for missing tickers and market data, or route them to a separate specialist.
  • Better memory. Store notes and lessons in a database or on Drive, and retrieve only the relevant ones with embeddings instead of reading all notes for a ticker (Lewis et al., 2020). Merge or rank lessons so they do not conflict.
  • A stronger test of lessons. Run many more articles, hold out articles that were not used to write the lessons, and repeat runs so the difference can be tested.
  • Parallel work. Analyze articles in parallel and use an orchestrator with workers for larger portfolios (Schluntz & Zhang, 2024), with token and cost tracking.
  • More sources and tools. Add SEC filings, earnings call transcripts and full article text, and let the agent decide when it needs a search or price lookup as in ReAct (Yao et al., 2023).
  • Human review. Add a person-in-the-loop step before anything is acted on, and log intermediate steps, timeouts and retries, which are the safeguards the course lists for agent pitfalls.
